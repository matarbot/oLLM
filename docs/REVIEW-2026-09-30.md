## What is genuinely well done

Stated briefly, because it calibrates trust in the rest of the document:

- **The `Backend` trait seam + scripted `FakeBackend` is textbook.**
  Protocol invariants (prefill-before-save, never-save-unconfirmed-position,
  never-restore-onto-processing-slot, second-sight-zero-prefill) are asserted
  on recorded call sequences — no GPU, no live fs, no run-date. This is the
  right testable spine to grow block sharing on.
- **The failing-test-first pattern is visible in `git log`, not just claimed:
  `6b7a356`/`3db5aa5` (abort), `bd851de`/`2049f3c` (sidecar-on-rename),
  `d92ced8`/`844d790` (session stickiness) are each a red commit followed by
  its green fix.
- **The disconnect-abort fix is architecturally right:** dropping the backend
  stream on client hangup lets llama.cpp cancel the generation itself
  (`lib.rs:559-567`); persisting rejected turns was the old failure.
- **Comments cite measured evidence (E1/E7/E12h) rather than vibes, and the
  R1–R3 write rules are documented where they are enforced**
  (`lib.rs:161-171`), with the durability ceremony (fsync → rename → fsync
  dir) done correctly in both publishers.
- **The sidecar-rides-rename bug was caught by a test first and fixed**
  (`test_slot_save_checkpoint_reuse` pattern, applied in-tree at
  `seed.rs:340-362`).

## What this changes in the block-sharing plan

One hard dependency and one scope addition, both small:

1. **#1 becomes a precondition of M-3** (fork block save/restore on silicon),
   not an aside: quota accounting must learn file *classes* — blob, block
   (`.attn`/`.recr`), sidecar (`.ckpt`), manifest (`.parts.json`) — in the
   same change that introduces block files, or the first real win (dedup)
   arrives with its own leak. This also answers the open quota question in
   `docs/design/block-sharing-v0.md` §8/§9 with data: today's overage is
   **sidecars, not blobs** — "clean stale blobs now" would not have helped.
2. **#2 gets a per-slot lease inside admission** (pick + mark atomic; re-check
   backend-reported state under the same lock). Cheap now; a Heisenbug under
   MyAgent concurrency later.

Everything else is scheduled debt: #3 and #4 collapse naturally when
`SeedDance` is wired into the admission path for the seed dance (M-2); #5
wants one product-side decision — **require `x-session-id` from MyAgent** and
treat the header-less fallback as best-effort — a client convention, not a
change here.

---

## Verdict

~1,800 lines of purposeful, seam-aware Rust with measured-evidence comments
and a real tests-first history. This is not a codebase in trouble. But the
disk ledger — the single most load-bearing subsystem for the mission — does
not currently count 72% of its own disk. Fix #1 and #2 first, then M-1.
